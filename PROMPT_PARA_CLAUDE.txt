# CONTEXTO DEL PROYECTO

## Que es Soil Rock

Soil Rock es una aplicacion web interna de gestion de proyectos de ingenieria (estudios de suelos, geotecnia, mecanica de rocas). La empresa ejecuta proyectos en sectores como mineria, construccion, energia e infraestructura en Peru. La app reemplaza el uso de Excel y correo electronico para gestionar el ciclo de vida completo de un proyecto: desde la oportunidad comercial hasta el cierre y cobro.

## Stack Tecnico

- Frontend: Next.js 16.2 con App Router y Turbopack, React 19, TypeScript
- Estilos: Tailwind CSS v4 + estilos inline en componentes
- Iconos: @tabler/icons-react
- ORM: Prisma 7.8 con cliente generado en app/generated/prisma
- Base de datos: PostgreSQL en Supabase
- Almacenamiento de archivos: Supabase Storage
- Plataforma de deploy: (por definir, actualmente desarrollo local)

# ARQUITECTURA DEL SISTEMA

## Capas de la aplicacion

1. FRONTEND (Next.js Pages + React Components)
   - app/dashboard/** → paginas del dashboard
   - app/components/ → componentes reutilizables (ProyectoView, Tabs)

2. API LAYER (Next.js Route Handlers)
   - app/api/proyectos/ → CRUD de proyectos
   - app/api/proyectos/[id]/ → detalle, edicion, cambio de fase
   - app/api/proyectos/[id]/documentos/ → gestion de documentos
   - app/api/proyectos/[id]/carpetas/ → gestion de carpetas
   - app/api/carpetas/ → operaciones sobre carpetas
   - app/api/proyectos/[id]/documentos/metadata/ → metadatos de documentos

3. BACKEND / ORM
   - Prisma como ORM sobre PostgreSQL
   - Migraciones versionadas en prisma/migrations/

4. ALMACENAMIENTO
   - Supabase Storage para archivos fisicos (PDFs, planos, imagenes)
   - La BD solo guarda la URL del archivo

## Estructura de rutas (Next.js App Router)

/ → redirect a /login
/login → autenticacion
/dashboard → KPIs generales
/dashboard/pipeline → kanban de oportunidades comerciales
/dashboard/pipeline/[id] → detalle de oportunidad
/dashboard/proyectos → lista de proyectos operativos
/dashboard/proyectos/[id] → detalle de proyecto (usa ProyectoView)
/dashboard/proyectos/nuevo → crear nuevo proyecto
/dashboard/clientes → lista de clientes
/dashboard/clientes/[id] → detalle de cliente + contactos
/dashboard/mis-tareas → tareas asignadas al usuario actual
/dashboard/usuarios → administracion de usuarios

## Componente central: ProyectoView

El componente ProyectoView.tsx es el nucleo de la aplicacion. Renderiza la vista de un proyecto con tabs que varian segun la fase:

- FASE PIPELINE (pre_proyecto, propuesta, negociacion, adjudicado, en_pausa):
  Tabs: Info General | Tareas | Documentos | Actividad

- FASE OPERATIVA (adjudicado, ejecucion, cierre, cerrado, cancelado):
  Tabs: Info General | Tareas | Documentos | Actividad | Ingenieria | Ejecucion
  (Valorizaciones y Facturacion: codigo existente pero tabs ocultos, en desarrollo)

Factura: id, proyecto_id FK, valorizacion_id FK (nullable), numero, monto, fecha_emision, fecha_vencimiento, estado (EstadoFactura), retencion_pct, monto_neto, metodo_pago

# CICLO DE VIDA DEL PROYECTO (flujo de fases)

pre_proyecto → propuesta → negociacion → adjudicado → ejecucion → cierre → cerrado
                                        ↓
                                     en_pausa ↔ adjudicado
En cualquier punto antes de ejecucion: → cancelado

Reglas:
- Las fases pre_proyecto hasta en_pausa se gestionan desde el modulo Pipeline (vista kanban)
- Desde adjudicado en adelante se activan los tabs operativos (Ingenieria, Ejecucion)
- El campo "codigo" se asigna al momento de crear el proyecto con formato SR{YY}.{NNN}

# FLUJO DE DOCUMENTOS

1. El usuario sube un archivo → va a Supabase Storage → se crea registro en BD con la URL
2. El documento puede estar en una carpeta (carpeta_id) o suelto (carpeta_id = null)
3. Las carpetas tienen un modulo: "documentos" (creadas por el usuario), "ingenieria" (3 secciones fijas con nombre sugerido ETIS: {codigo}_ETIS_{NombreProyecto}_V00), "ejecucion" (reportes de campo + documentos de operaciones)
4. Estado del documento evoluciona: borrador → enviado_cliente → con_observaciones / aprobado → etc.

---

# FLUJO FINANCIERO (en desarrollo)

Ejecucion en campo
→ Reporte de Campo (registro diario: personal, equipos, clima, incidentes)
→ Valorizacion (agrupacion de avance por periodo con partidas y metrados)
   → estados: en_elaboracion → enviada_cliente → aprobada → facturada
→ Factura vinculada a la valorizacion
   → estados: emitida → cobrada / vencida / anulada
→ Garantias: fiel_cumplimiento, garantia_tecnica, retencion_contractual
   → estados: retenida → en_gestion → recuperada
